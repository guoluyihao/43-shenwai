## 1. 术语表

| 术语 | 含义 |
|---|---|
| 基础数据 | 学校、年级、班级、学生、教师、任课关系、科目、选科等“人和关系”的数据 |
| 基础数据版本 | 某一时点基础数据的完整快照，发布后只读，供评价任务引用 |
| 考试 | 一次具体的考试活动，如“2026 届高三一模” |
| 入口考试 | 作为“起点”的考试，用于取学生的初始水平 |
| 评价考试 | 作为“终点”的考试，用于取学生当前水平（旧称“出口考试”） |
| 原始分 | 学生在某科目考试中实际取得的卷面分 |
| 高考赋分 | 原始分按新高考等级赋分规则转换后的分数，由外部提供 |
| 选科 | 学生的高考选考科目组合，含首选科目与再选科目 |
| 计算基础值 | 本次评价用于计算的分值口径，取“原始分”或“高考赋分” |
| 评价任务 | 一次完整的增值评价工作，包含两次考试、范围、口径、算法与结果 |
| 匹配 | 把入口考试与评价考试的学生、科目、选科、班级对齐的过程 |
| 增值 | 学生在两次考试之间相对位置的变化，而非绝对分数变化 |
| 等级 | 按同一范围内百分位划分的档位，如 G1、G2……G7 |
| 进退步 | 学生在两次考试之间位置上升、下降或保持的判定结果 |
| 评价结果 | 学生、班级、教师、年级/学校四个层面的增值结论 |
| 报告解读 | 在数据结果基础上生成的文字结论与建议 |
| 标准分 | 算法内部用于衡量“相对位置”的分值，不是高考赋分 |
| AI 解析 | 系统对上传的 Excel/CSV 文档进行结构识别、字段提取与内容理解的过程 |
| 解析置信度 | AI 对某个字段识别结果的确定程度，分为高、中、低三档；低置信度必须人工确认 |
| 原文定位 | 每个解析字段对应的原文件位置（工作表、行、列），用于人工核对 |
| 差异清单 | 解析结果与系统现有数据比对后形成的“新增、缺失、变更、冲突、异常”列表 |
| 导入批次 | 一次上传及其解析、匹配、确认、入库全过程的记录单元，可追溯、可回滚 |
| 回滚 | 撤销某个导入批次尚未发布的数据写入 |

> **特别说明**：本文件中出现“赋分”，一律指**高考赋分**，不是系统内部生成的分数。系统内部只使用“标准分”，不再产出“Z 赋分”。

## 2. 产品定位与目标

### 2.1 背景

学校做增值评价时普遍面临四个问题：

1. 每次评价都要重新上传一张大表，数据不能复用。
2. 学生转班、转学、改选科后，历史结果无法解释“当时是按什么口径算的”。
3. 评价方法只有一套，无法根据学校需求选择不同算法。
4. 结果只有数字，缺少能直接用于汇报和教研的解读。

### 2.2 产品目标

把增值评价从“一次性算分工具”升级为“**可持续运转的评价工作台**”：

- **数据资产化**：基础数据与考试成绩长期沉淀，一次维护、多次使用。
- **入口智能化**：直接上传学校现有的 Excel/CSV 文档，由 AI 解析并匹配，不再要求下载模板、手工填表。
- **口径可追溯**：哪一版基础数据、哪两次考试、用原始分还是赋分、用哪种算法，全部可查。
- **流程可控**：配置 → 匹配 → 算法 → 结果 → 报告，每一步都有确认关卡。
- **结果可解释**：不止给排名，还要说明“为什么”和“怎么办”。

### 2.3 核心价值

| 对象 | 价值 |
|---|---|
| 系统管理员 | 集中维护多校数据，上传学校现有文档即可完成导入，批量建评价，口径统一 |
| 学校管理员 | 随时查看本校评价结果与报告，无需重复整理数据 |
| 教师（经学校查看） | 看到自己班级、学科的增值表现，而非只有平均分 |
| 学校管理层 | 用增值结果做教学诊断与资源调整 |

| 考试建档、成绩导入与发布 | 可操作 | 查看本校 |
| 上传 Excel/CSV 文档 | 可操作 | 不可 |
| 查看 AI 解析结果与差异清单 | 可操作 | 查看本校 |
| 修正解析结果、确认入库 | 可操作 | 不可 |
| 查看导入批次、回滚未发布数据 | 可操作 | 查看本校 |
| 新建、配置评价任务 | 可操作 | 不可 |
| 查看匹配结果与异常清单 | 可操作 | 查看本校 |
| 确认匹配结果 | 可操作 | 不可 |

| 触发计算、重算 | 可操作 | 不可 |
| 查看评价结果、图表、报告 | 全部学校 | 本校 |

### 3.3 数据隔离规则

- 学校管理员只能看到所属学校的学校信息、基础数据、考试、评价任务与结果。
- 跨学校数据不可见、不可搜索、不可导出。
- 系统管理员可按学校切换查看。

## 4. 总体业务流程

### 4.1 主流程

```
① 维护基础数据
   学校 / 年级 / 班级 / 学生 / 教师 / 任课关系 / 科目 / 选科
        │
        ▼
② 发布基础数据版本（快照，发布后只读）
        │
        ▼
③ 建立考试并导入成绩
   上传 Excel/CSV → AI 解析 → 自动匹配 → 差异确认 → 入库
   每人每科：原始分、高考赋分（可空）、选科、缺考标记
        │
        ▼
④ 新建评价任务
   基础数据版本 + 入口考试 + 评价考试 + 评价范围
   + 计算基础值口径（默认按科目类型带出，可逐科覆盖）
        │
        ▼
⑤ 数据匹配与处理
   学生对齐 → 科目对齐 → 选科核对 → 班级核对
   → 匹配结果 + 异常清单 → 人工确认
        │
        ▼
⑥ 选择算法与参数
   标准分增值法 / 等级差法 + 等级档数、阈值、权重等
        │
        ▼
⑦ 计算并输出结果
   学生级 → 班级级 → 教师级 → 年级/学校级
        │
        ▼
⑧ 呈现与报告解读
   图表 / 排名 / 下钻 / 文字结论 / 导出
```

> 数据入口原则：**不要求用户下载模板**。用户上传学校现有的 Excel/CSV 文档，系统负责理解、匹配与差异提示，人只做确认和修正。

### 4.2 四个必经闸门

| 闸门 | 不通过时的限制 |
|---|---|
| 导入差异未确认 | 解析结果不写入系统，不进入正式数据 |
| 基础数据版本未发布 | 不能新建评价任务 |
| 匹配结果未确认 | 不能进入算法选择与计算 |
| 算法与参数未确认 | 不能触发计算 |

### 4.3 评价任务状态机

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| 草稿 | 已建但配置未完成 | 编辑、删除 |
| 待匹配 | 两次考试与范围已配置 | 发起匹配 |
| 匹配中 | 系统正在对齐数据 | 查看进度 |
| 匹配待确认 | 匹配完成，存在需确认项 | 查看异常、修正、确认 |
| 待计算 | 匹配已锁定，算法未确认 | 选择算法与参数 |
| 计算中 | 正在生成结果 | 查看进度 |
| 已完成 | 结果与报告可查看 | 查看、重算、归档 |
| 失败 | 计算中断 | 查看原因、重新计算、删除 |
| 已归档 | 不再参与日常列表 | 查看、恢复 |

### 4.4 端到端场景

**系统管理员：**

1. 维护学校、班级、学生、教师、任课与选科。
2. 发布“2026 届高三基础数据 v3”。
3. 建立“高三一模”“高三二模”两次考试，上传学校现有成绩文档，AI 解析后确认差异并入库。
4. 新建评价任务：选 v3 版本、入口=一模、评价=二模、范围=高三、口径=选考科目用赋分、必考科目用原始分。
5. 发起匹配，处理“转学生”“换班生”“赋分缺失”等异常，确认匹配。
6. 选择“标准分增值法”，设定等级档数与阈值，触发计算。
7. 查看学生/班级/教师结果，编辑报告解读，导出 Excel 与 PDF。

**学校管理员：**

1. 登录后进入本校评价列表。
2. 打开已完成任务，查看总体结论、学科表现、班级与教师排名。
3. 下钻到班级、教师、学生明细。
4. 下载报告与导出数据，用于校内会议。

## 5. 基础数据管理

### 5.1 学校

| 项目 | 规则 |
|---|---|
| 学校名称 | 必填，全局唯一 |
| 学校编码 | 必填，全局唯一，用于外部数据对接 |
| 状态 | 启用 / 停用；停用后该校管理员无法登录，数据保留 |
| 学校管理员 | 每校至少一名；由系统管理员创建、重置密码、停用 |

### 5.2 年级与班级

- 年级：名称（如“2026 届”）、学段（高中/初中）、入学年份。
- 班级：名称、所属年级、班主任（可空）、状态（在读/已毕业）。
- 班级名称在同一学校同一届内唯一。

### 5.3 学生

| 字段 | 规则 |
|---|---|
| 学籍号 | 必填，全局唯一，匹配主键 |
| 身份证号 | 可空；填写时校验格式与唯一性 |
| 姓名 | 必填 |
| 学校/年级/班级 | 必填 |
| 选科组合 | 必填；含首选科目与再选科目 |
| 状态 | 在读 / 转学 / 休学 / 毕业 / 其他 |
| 备注 | 可空 |

规则：

- 学生转班不新增学生，只变更班级并记录变更时间。
- 学生转学、休学不改历史成绩，只改状态。
- 删除学生仅允许在无任何成绩引用时执行；否则只能停用。

### 5.4 教师

| 字段 | 规则 |
|---|---|
| 工号 | 必填，全局唯一 |
| 姓名 | 必填 |
| 学校 | 必填 |
| 状态 | 在职 / 离职 |

### 5.5 任课关系

- 一条记录表示：某教师在某班级任教某科目。
- 同一班级同一科目可有多名教师（如主备教），需标记“是否主责”。
- 教师评价默认按“主责教师”归属；无主责标记时按全部任课教师归属并提示。

### 5.6 科目

| 字段 | 规则 |
|---|---|
| 科目名称 | 必填，同校唯一 |
| 科目类型 | 必考 / 首选 / 再选 |
| 计分方式 | 原始分 / 等级赋分 |
| 满分 | 必填 |
| 排序 | 用于列表、导出、报告中的科目顺序 |
| 是否计入总分 | 必填 |

- 必考科目（语文、数学、外语）通常为原始分。
- 选考科目（首选、再选）通常为等级赋分。
- 计分方式只作为**建任务时的默认值**，可在评价任务中逐科覆盖。

### 5.7 选科

- 默认支持“3+1+2”：首选 1 门（物理/历史）+ 再选 2 门（化学/生物/政治/地理）。
- 选科组合作为学生属性保存，不随每次考试重复录入。
- 成绩录入时校验：学生实际报考科目必须与选科组合一致；不一致时进入异常清单。

### 5.8 基础数据版本

| 项目 | 规则 |
|---|---|
| 版本号 | 自动生成，如 v1、v2、v3 |
| 版本名称 | 必填，如“高二选科分班后” |
| 发布时间 / 发布人 | 系统记录 |
| 变更说明 | 必填，简述本版改了什么 |
| 状态 | 草稿 / 已发布 / 已停用 |

规则：

1. **发布即快照**：发布后该版本内容只读，任何修改都产生新版本。
2. **评价任务必须引用已发布版本**；草稿版本不可被引用。
3. **历史任务继续引用旧版本**：旧版本停用后，已有任务仍可查看与重算。
4. **版本差异**：支持查看两个版本之间“新增/转出学生、班级变更、任课变更、选科变更”的差异清单。
5. 同一学校同一时间只允许一个“当前版本”用于新建任务。

### 5.9 基础数据校验

- 学籍号、工号、学校编码全局唯一。
- 学生必须归属班级；班级必须归属年级。
- 任课关系中的教师、班级、科目必须存在且属于同一学校。
- 选科组合中的科目必须存在且类型匹配。
- 发布版本前必须通过完整性校验，校验不通过不允许发布。

### 5.10 基础数据导入

基础数据同样支持“上传文档 → AI 解析 → 匹配 → 差异确认 → 入库”，不再要求下载模板。

| 文档类型 | 可导入内容 |
|---|---|
| 学生名册 | 学籍号、姓名、身份证号、班级、选科组合、状态 |
| 教师名单 | 工号、姓名、学校、状态 |
| 任课安排 | 教师、班级、科目、是否主责 |

规则：

1. 基础数据导入与成绩导入共用同一套导入向导与差异确认机制。
2. 导入前必须选择目标学校；AI 解析结果不得跨校写入。
3. 新增学生、班级变更、选科变更必须人工确认，不允许静默覆盖。
4. 未确认的解析结果不写入基础数据，也不产生新版本。
5. 导入完成后，由系统管理员决定是否发布新的基础数据版本。

## 6. 考试与成绩管理

### 6.1 考试建档

| 字段 | 规则 |
|---|---|
| 考试名称 | 必填，同校同年级建议唯一 |
| 考试类型 | 入口考试 / 评价考试 / 诊断考试 / 其他 |
| 所属学期 | 必填 |
| 适用年级 | 必填，可选择多个 |
| 考试日期 | 必填 |
| 参与范围 | 年级或指定班级 |
| 状态 | 草稿 / 已发布 / 已归档 |

规则：

- 考试发布后，成绩才可被评价任务引用。
- 已发布考试的成绩不可直接修改；需“作废重发”并记录原因。
- 归档考试不再出现在新建任务的默认列表中，但历史任务仍可查看。

### 6.2 数据导入总览（重点）

成绩与基础数据统一采用**“上传 → AI 解析 → 匹配 → 差异确认 → 入库”**五步链路。

| 步骤 | 用户动作 | 系统动作 |
|---|---|---|
| 1. 上传 | 选择或拖入学校现有 Excel/CSV 文件 | 识别文件、保存原件、创建导入批次 |
| 2. 解析 | 等待并查看解析进度 | 识别表头与结构，提取字段，标注置信度与原文位置 |
| 3. 匹配 | 核对匹配结果 | 按学籍号、身份证号、姓名+班级匹配学生；归一班级、科目、教师 |
| 4. 确认 | 逐项处理差异 | 汇总阻断、待确认、提示三类差异，给出处理建议 |
| 5. 入库 | 确认并提交 | 写入数据，生成导入报告，保留完整记录 |

规则：

1. **不要求下载模板**，用户直接上传学校现有的成绩单、名册、任课表。
2. 文件类型限定为 **Excel（.xlsx/.xls）与 CSV**；不接收 PDF、图片、Word。
3. 一次可上传多个文件，系统按批次合并解析；跨考试、跨年级的内容由 AI 拆分并给出归属建议。
4. **未确认不入库**：解析结果先进入“待确认”状态，不写入正式数据。
5. 手工录入作为兜底保留，但不再是主入口。

### 6.3 AI 解析规则

| 能力 | 要求 |
|---|---|
| 结构识别 | 识别多工作表、多级表头、合并单元格、空行空列、跨页续表 |
| 字段提取 | 学籍号、姓名、身份证号、班级、科目、教师、原始分、高考赋分、选科、缺考标记 |
| 别名归一 | 科目简称（语/语文、英/外语）、班级写法（高三1班/高三(1)班/1班）、教师姓名空格与全半角 |
| 置信度 | 每个字段给出高/中/低置信度；低于阈值（默认 80%）必须人工确认 |
| 原文定位 | 每个字段可回溯到工作表、行、列，便于对照原文件 |
| 异常识别 | 空值、重复、分数越界、科目不识别、表头缺失、文件损坏 |
| 多文件合并 | 同一批次内多份文件可合并为一份结果；重复内容提示合并或忽略 |

解析结果必须以**“左原文、右结构化”**的方式呈现，用户能边看原文边核对。

### 6.4 差异清单与确认

差异分三级：

| 级别 | 含义 | 处理要求 |
|---|---|---|
| 阻断 | 无法识别学生、重复记录、分数越界、文件损坏、关键字段缺失 | 必须逐条处理，清零后才能入库 |
| 待确认 | 新增学生、缺失学生、班级变更、选科变更、赋分缺失、考试归属不明 | 必须逐条确认或批量确认 |
| 提示 | 低置信度字段、科目别名、格式不统一、空行空列 | 可查看后批量接受 |

确认动作：

- 接受系统建议
- 手工修正
- 关联到系统已有学生/教师/班级
- 新增到基础数据
- 忽略该条
- 整行/整份文件排除

差异确认页必须同时展示：差异总数、各级别数量、已处理数量、剩余阻断数量。

### 6.5 导入批次、回滚与审计

| 项目 | 规则 |
|---|---|
| 批次号 | 自动生成，如 `IMP-20260508-01` |
| 批次内容 | 原始文件、解析结果、匹配结果、差异处理、确认人、时间、解析版本 |
| 状态 | 解析中 / 待确认 / 已入库 / 已回滚 / 失败 |
| 回滚 | 仅允许回滚“已入库且未发布”的数据；已发布数据需作废重发 |
| 审计 | 原始文件长期保留，任何一次修改都记录修改前后值与操作人 |
| 导入报告 | 记录成功数、跳过数、失败数、差异明细，可导出 |

### 6.6 成绩字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 学生 | 是 | 必须在考试参与范围内 |
| 科目 | 是 | 必须在该考试科目范围内 |
| 原始分 | 是 | 数值，须在 0 ~ 满分之间 |
| 高考赋分 | 否 | 数值，通常为 30 ~ 100；无则为空 |
| 选科标记 | 是 | 必考 / 首选 / 再选 |
| 缺考标记 | 是 | 正常 / 缺考 / 免考 |
| 备注 | 否 | 异常说明 |

### 6.7 赋分规则（重点）

1. **高考赋分由外部提供**，系统不负责按新高考规则计算。
2. **有就存**：导入或录入时提供赋分，则按原值保存。
3. **没有就不造**：赋分为空时保持为空，不自动补算、不默认等于原始分。
4. **只做合理性校验**：范围是否合理、是否与原始分同时存在、选考科目是否大面积缺失。
5. **评价时再决定用不用**：是否使用赋分由评价任务的计算基础值配置决定。

### 6.8 成绩发布与修订

- 草稿成绩可反复修改。
- 发布后只读；发现错误需“作废重发”，系统保留原发布记录与作废原因。
- 同一学生同一科目在同一考试中只允许一条有效成绩。
- 重复记录直接阻断发布，必须处理。

### 6.9 成绩校验清单

| 校验项 | 处理方式 |
|---|---|
| 学生不在考试范围 | 阻断，提示具体学生 |
| 科目不在考试范围 | 阻断 |
| 原始分为空 | 阻断 |
| 原始分超出 0~满分 | 阻断 |
| 赋分超出合理范围 | 警告，允许人工确认 |
| 选科标记与选科组合不一致 | 警告，进入异常清单 |
| 同一学生同一科目重复 | 阻断 |
| 缺考但填写了分数 | 阻断 |

## 7. 评价任务管理

### 7.1 新建与配置

| 配置项 | 规则 |
|---|---|
| 任务名称 | 必填，如“2026 届高三一模→二模增值评价” |
| 所属学校 | 必填，决定数据范围 |
| 基础数据版本 | 必填，只能选已发布版本 |
| 入口考试 | 必填，只能选已发布考试 |
| 评价考试 | 必填，只能选已发布考试 |
| 评价范围 | 年级/班级/科目，可多选 |
| 计算基础值 | 任务级默认 + 科目级覆盖（见 7.2） |
| 算法 | 匹配确认后选择（见第 9 章） |
| 参数 | 随算法配置，保存为任务快照 |

规则：

- 入口考试日期必须早于评价考试日期，否则阻断。
- 两次考试的参与范围必须有交集，无交集不允许建任务。
- 允许跨年级、跨学期评价，但需在任务中明确提示。

### 7.2 计算基础值口径

这是本版新增的核心配置。

| 层级 | 规则 |
|---|---|
| 任务级默认 | 建任务时选择“原始分”或“高考赋分”作为默认口径 |
| 科目级覆盖 | 可对单个科目单独指定口径，覆盖任务默认值 |
| 默认带出 | 根据科目主数据的“计分方式”自动带出：必考科目默认原始分，选考科目默认赋分 |
| 一致性 | 同一科目在同一任务内只能使用一种口径，不允许混用 |
| 缺赋分回退 | 某科目赋分缺失时，该科目**整科**回退为原始分，并在任务中显式提示 |
| 结果标注 | 结果页、导出文件、报告必须标注“本次计算基础值” |

示例：

| 科目 | 科目计分方式 | 任务默认 | 本科目实际口径 |
|---|---|---|---|
| 语文 | 原始分 | 原始分 | 原始分 |
| 数学 | 原始分 | 原始分 | 原始分 |
| 外语 | 原始分 | 原始分 | 原始分 |
| 物理 | 等级赋分 | 原始分 | 赋分（逐科覆盖） |
| 化学 | 等级赋分 | 原始分 | 赋分（逐科覆盖） |

### 7.3 评价范围

- 可按年级、班级、科目组合筛选。
- 范围一经确认，参与计算的学生与科目即锁定；如需调整，需回到配置并重新匹配。
- 范围外的学生不进入结果，但仍在匹配报告中以“范围外”统计。

### 7.4 评价任务的生命周期

- 草稿可删除。
- 已产生结果的任务不可删除，只能归档。
- 重算不覆盖旧结果，生成新结果版本（R1、R2……），并记录重算原因、算法与参数快照。

## 8. 数据匹配与异常处理

匹配分两层，规则共用：

1. **导入匹配**：AI 解析出的成绩/名单与基础数据匹配（学生、班级、教师、科目、选科）。
2. **评价匹配**：入口考试与评价考试的学生对齐，形成可计算的样本。

### 8.1 匹配顺序（两层通用）

1. 学籍号完全一致。
2. 学籍号缺失时，用身份证号一致。
3. 仍无法匹配时，进入“待人工匹配”，可按姓名 + 班级辅助查找，但必须人工确认。

### 8.2 匹配结果分类

| 分类 | 含义 |
|---|---|
| 双方匹配 | 两次考试都有该学生，可参与计算 |
| 仅入口 | 只在入口考试中出现 |
| 仅评价 | 只在评价考试中出现 |
| 信息冲突 | 姓名、班级、选科、科目不一致 |
| 重复记录 | 同一学生同一科目出现多条 |
| 导入新增 | 文档中有、系统基础数据中没有的学生/教师/班级 |
| 导入缺失 | 系统基础数据中有、文档中没有的学生/教师 |
| 字段变更 | 姓名、班级、选科、任课等与基础数据不一致 |

### 8.3 异常处理规则

| 异常 | 默认处理 | 可人工操作 |
|---|---|---|
| 仅入口考试有 | 剔除，不计入结果 | 纳入（如转出学生仍要评价）或保持剔除 |
| 仅评价考试有 | 剔除，不计入结果 | 纳入（如转入学生按入口缺失处理）或保持剔除 |
| 姓名不一致 | 标记冲突，暂不参与 | 确认后修正或剔除 |
| 班级不一致 | 以任务指定版本为准，标记“班级变更” | 选择按入口班级或评价班级归属 |
| 选科不一致 | 标记，涉及科目暂不参与 | 排除变化科目或整生剔除 |
| 科目缺失 | 该科目不参与 | 排除该科目或整生剔除 |
| 缺考 | 该科目不参与计算 | 保持排除 |
| 0 分 | 标记异常，暂不参与 | 确认为真实 0 分后纳入 |
| 重复记录 | 阻断匹配 | 删除重复或指定有效记录 |
| 分数越界 | 阻断匹配 | 修正后重新匹配 |
| 导入文档新增学生 | 暂不写入 | 新增到基础数据 / 关联已有 / 排除 |
| 导入文档缺失学生 | 提示，不自动删除 | 标记缺考 / 忽略 / 补录 |
| 低置信度字段 | 暂不采用 | 人工修正 / 接受建议 / 排除 |
| 文件内容跨考试 | 暂停入库 | 按 AI 建议确认归属 |
| 文件损坏或无法解析 | 阻断 | 重新上传 / 改用手工录入 |

### 8.4 匹配确认

- 匹配完成后生成“匹配结果概览”：匹配成功数、仅入口数、仅评价数、冲突数、剔除数。
- 所有阻断级异常处理完成后，才能点击“确认匹配”。
- 确认后匹配结果锁定，并生成匹配报告；如需修改，必须“撤销确认”并重新匹配。
- 确认人与确认时间必须记录。
- **导入差异确认与评价任务匹配确认是两次独立确认，互不替代。**

### 8.5 匹配报告内容

- 入口考试参与人数、评价考试参与人数、成功匹配人数。
- 各类异常数量与明细。
- 剔除学生清单及原因。
- 实际参与计算的样本量与科目覆盖情况。
- 样本不足提示（见 9.8）。

## 9. 增值算法

### 9.1 共同前置

1. 只使用匹配成功且在评价范围内的学生。
2. 按科目分组；总分按选科类别分组。
3. 每个科目使用任务中确定的计算基础值（原始分或高考赋分）。
4. 缺考、剔除、分数缺失的记录不参与该科目计算。
5. 同一科目内不得混用两种分值口径。

### 9.2 算法一：标准分增值法（Z 分差法）

**适用场景**：生源差异大、需要精细区分学生位置变化、希望弱化科目难度差异。

**计算步骤（业务表述）：**

1. 对入口考试某科目，计算全体参与学生的平均分与分差水平（标准差）。
2. 把每个学生的分数转换成“相对位置分”：

   > 相对位置分 =（本人分数 − 平均分）÷ 标准差

3. 对评价考试同一科目重复上述步骤。
4. 计算位置变化：

   > 位置变化 = 评价考试相对位置分 − 入口考试相对位置分

5. 判定进退步：

   | 位置变化 | 判定 | 进退步级数 |
   |---|---|---|
   | 绝对值 < 0.25 | 保持 | 0 |
   | ≥ 0.25 | 进步 | 1 + 向下取整（（变化值 − 0.25）÷ 0.5） |
   | ≤ −0.25 | 退步 | 负的（1 + 向下取整（（绝对值 − 0.25）÷ 0.5）） |

**业务含义：**
- 0.25 个标准差以内视为正常波动，不奖不罚。
- 超过 0.25 后，每多 0.5 个标准差，多算一级。
- 例：变化 +0.58 → 进步 1 级；变化 −0.51 → 退步 1 级；变化 +1.10 → 进步 2 级。

### 9.3 算法二：等级差法

**适用场景**：面向教师、家长解释，强调“进了几档、掉了几档”，直观易懂。

**计算步骤：**

1. 对入口考试某科目，按百分位把学生划入等级（档数由任务参数决定）。
2. 对评价考试同一科目，用相同档数划等级。
3. 计算等级差：

   > 等级差 = 入口档位序号 − 评价档位序号

   - 结果为正 → 进步（档位数字变小，名次更靠前）
   - 结果为负 → 退步
   - 结果为 0 → 保持

4. 进退步级数 = 等级差的绝对值。

**业务含义：**
- 只看“跨了几档”，不看档内具体分差。
- 优点：解释成本低；缺点：同档内的明显变化会被忽略。
- 建议与标准分法配合使用：标准分法看精细变化，等级差法看整体升降。

### 9.4 两种算法对比

| 维度 | 标准分增值法 | 等级差法 |
|---|---|---|
| 敏感度 | 高，能反映档内变化 | 低，只看跨档 |
| 解释难度 | 中，需要解释“标准差” | 低，直接说“进了几档” |
| 抗极端值 | 较好 | 好 |
| 适合对象 | 教务、教研分析 | 教师、家长沟通 |
| 推荐用途 | 主评价口径 | 辅助解读口径 |

### 9.5 等级划分

| 档数 | 各档百分位上限 | 权重（从高到低） |
|---|---|---|
| 7 档（默认） | 5%、15%、35%、65%、85%、95%、100% | 90、76.7、63.3、50、36.7、23.3、10 |
| 9 档（可选预设） | 4%、10.5%、22.6%、40.1%、59.9%、77.4%、89.5%、96%、100% | 90、80、70、60、50、40、30、20、10 |
| 自定义 | 2~15 档，逐档设置上限，最后一档必须为 100% | 按公式在 90 与 10 之间等距分配 |

规则：

- 档数在评价任务中配置，默认 7 档。
- 同一任务内所有科目使用同一档数，保证可比。
- 总分按“首选科目”分组划档（历史类、物理类分别划），避免不同选科直接比较。

### 9.6 汇总指标

| 指标 | 业务含义 | 计算口径 |
|---|---|---|
| 学业实力 | 本次整体水平 | 本次各等级人数占比 × 等级权重，求和 |
| 保持值 | 原本靠前的学生保持住的价值 | 仅统计“保持”学生，按其入口等级权重减 10 后加权 |
| 进步值 | 进步学生带来的增量 | 仅统计“进步”学生，从入口等级向上逐级累加等级权重 |
| 退步值 | 退步学生带来的减量 | 仅统计“退步”学生，从入口等级向下逐级累加（100 − 权重） |
| 相对进步率 | 综合进步与退步的核心指标 | （保持值 + 进步值 × 2）÷（（退步值 + 1）× 1.5） |
| 平均进退步级数 | 群体平均变化幅度 | 参与计算学生的进退步级数平均值 |
| 进步学生占比 | 进步面 | 进步人数 ÷ 参与计算人数 |
| 退步学生占比 | 退步面 | 退步人数 ÷ 参与计算人数 |

> 相对进步率的业务解释：保持和进步是“加分项”，其中进步按双倍计；退步是“减分项”，放在分母并额外放大 1.5 倍，避免退步多的群体因进步值高而排名虚高。

### 9.7 排名规则

| 排名 | 依据 | 范围 |
|---|---|---|
| 实力排名 | 学业实力 | 评价范围内同科目全体对象 |
| 进步率排名 | 相对进步率 | 评价范围内同科目全体对象 |
| 学生进步排名 | 进退步级数 | 同科目、同范围，可选 |

规则：

- 排名范围为“同科目、同评价范围”，**不随页面筛选变化**。
- 班级排名与教师排名的对象集合不同，互不混排。
- 样本量不足（默认少于 8 人）的对象不参与排名，并标注“样本不足”。
- 同分/同级并列时，名次并列，下一名次跳号。

### 9.8 边界规则

| 场景 | 处理 |
|---|---|
| 组内全员同分 | 标准分统一为 0，全部判定为保持 |
| 组内仅 1 人 | 该科目不计算标准分，不参与排名，标注“样本不足” |
| 缺考 | 该科目不参与计算，不计入分母 |
| 极端分数 | 不剔除，按实际分数计算；报告中提示“存在极端值” |
| 赋分缺失 | 该科目整科回退原始分，并在任务与报告中标注 |
| 选科变化 | 变化前后科目不可直接比较，按异常处理规则排除或人工确认 |
| 跨年级评价 | 允许，但报告必须注明“入口与评价考试分属不同年级” |

### 9.9 计算示例（标准分法）

某科目 4 名学生：

| 学生 | 入口分 | 评价分 |
|---|---|---|
| A | 90 | 88 |
| B | 80 | 92 |
| C | 70 | 75 |
| D | 60 | 65 |

1. 入口平均 75，分差水平约 12.9；评价平均 80，分差水平约 12.4。
2. 入口相对位置分：A +1.16、B +0.39、C −0.39、D −1.16。
3. 评价相对位置分：A +0.65、B +0.97、C −0.40、D −1.21。
4. 位置变化：A −0.51、B +0.58、C −0.01、D −0.05。
5. 判定：A 退步 1 级；B 进步 1 级；C、D 保持。

> 结论：A 虽然只从 90 降到 88，但相对位置明显下滑；B 从 80 升到 92，相对位置上升。这正是“增值”与“绝对分”的差别。

## 10. 结果输出与呈现

### 10.1 学生结果

字段：

- 学籍号、姓名、班级、选科组合

- 原始分、高考赋分（如有，分列展示）
- 入口等级、评价等级、等级变化

功能：

- 按姓名、班级、科目、进退步状态筛选。

- 图表：相对进步率对比、学业实力对比、保持/进步/退步构成。
- 下钻：点击班级进入该班学生明细。

- 指标与班级评价一致。
- 支持按科目、班级筛选。
- 两套排名：实力排名、进步率排名。
- 下钻：点击教师查看其任教班级与学生名单。

### 10.4 教师看板

  - **总分教师**（班主任/总分负责人）：选择班级，查看该班“总分 + 各科”指标与排名，可下钻学生矩阵。
  - **学科教师**：选择科目，查看本人该科目指标与排名，以及所教班级的指标列表，可下钻学生矩阵。

- 指标多选：入口分、评价分、原始分、高考赋分、入口等级、评价等级、等级变化、相对位置分、进退步情况、进退步级数。

- 双层表头滚动锁定，左侧学生信息固定。
- 单元格按进退步状态着色。
- 点击学生姓名查看全科明细。
- 本期不分页，全量展示范围内的学生；超过 500 人时提示“建议缩小范围”。

### 10.6 年级/学校总览

- 参与评价人数、匹配成功率、剔除人数。
- 整体平均进退步级数、进步/保持/退步占比。
- 各科目相对进步率对比。
- 各班进步率分布。
- 样本不足与数据质量提示。

### 10.7 通用交互规则

- 筛选条件在翻页、切换 Tab 时保留。
- 所有结果页固定展示“本次口径、算法、参数、样本量”摘要。
- 无数据、样本不足、匹配异常时给出明确提示，不展示空白表格。
- 导出内容必须与页面当前筛选一致，并在文件内注明口径与算法。

## 11. 报告解读

### 11.1 报告结构

1. **评价概况**：学校、年级、范围、入口/评价考试、样本量、计算基础值、算法与参数。
2. **总体结论**：整体进步/退步态势、进步面与退步面。
3. **学科表现**：各科相对进步率、强弱科对比、异常科目。
4. **班级表现**：领先班级、进步显著班级、需关注班级。
5. **教师表现**：领先教师、进步显著教师、需关注教师。
6. **学生群体特征**：进步/保持/退步分布，高分段与低分段变化。
7. **数据质量提示**：匹配剔除、赋分缺失、样本不足、极端值。
8. **建议**：教学改进、班级管理、后续评价安排。

### 11.2 生成规则

- 由系统按规则模板自动生成初稿，系统管理员可编辑。
- 每条结论必须能对应到具体数据，不允许无依据的因果判断。
- 涉及排名时注明“同科目、同范围内”。
- 涉及样本不足时，先提示局限，再给结论。
- 报告中不得出现“学生个人能力评价”“教师教学水平定性”等越界表述。

### 11.3 模板示例

| 触发条件 | 生成结论（示例） |
|---|---|
| 相对进步率 > 1.1 且进步学生占比 > 40% | 本次评价整体呈上升态势，进步面较广，多数学生相对位置有所提升。 |
| 相对进步率 < 0.9 且退步学生占比 > 40% | 本次评价整体承压，退步面偏大，建议重点关注中低分段学生的稳定性。 |
| 某科目相对进步率显著低于其他科目 | 本科目相对进步率低于全校平均水平，建议结合试卷难度与教学进度进一步分析。 |
| 高分段学生退步占比高 | 高分段学生出现流失迹象，建议关注尖子生群体的稳定性与心理状态。 |
| 低分段学生进步占比高 | 低分段学生提升明显，说明基础巩固措施初见成效。 |
| 样本不足 | 本对象参与计算人数不足 8 人，排名与结论仅供参考。 |
| 赋分缺失 | 本次评价中 X 科目因赋分缺失，已按原始分计算，跨科目比较需谨慎。 |
| 匹配剔除较多 | 本次评价剔除 X 人（占 Y%），主要原因为转学、缺考与信息不一致，结论代表性可能受影响。 |

### 11.4 编辑与版本

- 报告初稿自动生成后，系统管理员可编辑文字、调整段落顺序。
- 每次编辑保留版本，记录编辑人与时间。
- 学校管理员只能查看最终版，不能编辑。
- 报告随结果版本绑定：重算后生成新报告版本，旧报告保留可查。
