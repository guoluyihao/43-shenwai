# 成绩增值评价系统：计算逻辑与算法说明（详细版）

本文档说明系统在“导入成绩 → 计算模型 → 数据评价”的主要算法逻辑、公式与边界规则，便于复核与后续迭代。

## 1. 输入数据与核心字段

### 1.1 Excel 输入字段（固定表头）
- 学籍号/身份证号（studentId）
- 姓名（studentName）
- 班级（className）
- 科目（subject）
- 教师（teacher）
- 入口分数（entryScore）
- 本次分数（currentScore）

### 1.2 成绩明细表（ScoreRecord）关键字段
- projectId：项目隔离
- entryScore / currentScore：入口/本次原始分
- selectionCategory：选科分类（历史类/物理类/未分科）
- entryRank / currentRank：入口/本次排名（同分并列）
- entryGrade / currentGrade：入口/本次等级（G1~G9）
- entryZScore / currentZScore：入口/本次 Z 分数
- entryZAssigned / currentZAssigned：入口/本次 Z 赋分（分段线性插值）
- zAssignedDiff：Z 赋分差值（current - entry）
- progressStatus：进退步情况（保持/进步/退步）
- progressValue：进退步等级（保持为0，进步为正，退步为负）

## 2. 选科分类（selectionCategory）

### 2.1 分类规则（按学生维度回填）
对同一项目内同一学生（student_id）的所有科目记录进行识别：
- 若存在科目包含“历史” → selectionCategory = 历史类
- 否则若存在科目包含“物理” → selectionCategory = 物理类
- 否则 → selectionCategory = 未分科

### 2.2 目的
用于“总分”科目下的分组计算：总分需要按选科类别区分统计口径（如总分_历史类、总分_物理类、总分_未分科）。

## 3. 计算模型（数据计算）总体流程

以一个项目（project_id）为计算范围，取出项目内所有 ScoreRecord。

### 3.1 分组策略（groupKey）
- 若 subject != 总分：按 subject 分组
- 若 subject == 总分：按 `总分 + "_" + selectionCategory` 分组
  - selectionCategory 为空时按“未分科”处理

这意味着：
- 各学科（语文/数学/…）在全项目范围按学科统一统计
- 总分在不同选科类别下独立统计（均值、标准差、排名、等级、赋分都分开）

### 3.2 两套计算：入口分数与本次分数
同一组内会分别对：
- 入口分数（ENTRY）
- 本次分数（CURRENT）
执行相同的统计与赋值流程：
- 均值与标准差
- 排名
- Z 分数
- 等级（G1~G9）
- Z 赋分（ZAssigned）

## 4. 统计量：均值与标准差

对某一 groupKey 下的所有学生记录（同一入口或本次）：

### 4.1 均值（mean）
mean = Σ(score) / n

### 4.2 标准差（stdDev）
使用样本标准差（Sample StdDev）：
- 若 n > 1：stdDev = sqrt( Σ(score - mean)^2 / (n - 1) )
- 若 n == 1：stdDev = 0

### 4.3 统计落库（SubjectStatistics）
每个 groupKey、scoreType（ENTRY/CURRENT）都会落一条统计记录：
- subject（总分/语文/…）
- selectionCategory（仅总分分组会有）
- scoreType（ENTRY/CURRENT）
- mean、stdDev、studentCount

## 5. 排名（Rank）

### 5.1 排序规则
组内按分数降序排列（高分在前）。

### 5.2 同分并列规则
遍历排序后的列表（下标 i 从 0 开始）：
- 若当前分数与上一条分数相同：rank 不变（并列同名次）
- 否则：rank = i + 1

### 5.3 注意点
这里的 rank 作为后续 percentile（分位）计算依据，因此同分会导致同一分数的学生在等级划分上共享相同 rank。

## 6. Z 分数（ZScore）

对组内每条记录：
- 若 stdDev == 0：z = 0
- 否则：z = (score - mean) / stdDev

Z 分数用于描述学生相对于组均值的标准差位置。

## 7. 等级（Grade，G1~G9）

### 7.1 分位定义
percentile = rank / n
其中 rank 为并列名次（1~n），n 为组内人数。

### 7.2 等级阈值（由高到低）
- percentile ≤ 0.040 → G1
- ≤ 0.105 → G2
- ≤ 0.226 → G3
- ≤ 0.401 → G4
- ≤ 0.599 → G5
- ≤ 0.774 → G6
- ≤ 0.895 → G7
- ≤ 0.960 → G8
- 否则 → G9

直观理解：G1 是最靠前（最优）的一段，G9 是最靠后（最弱）的一段。

## 8. Z 赋分（ZAssigned）

### 8.1 目标
将“同一等级区间内的原始分”映射到“该等级对应的 Z 分数带宽区间”，使得：
- 等级间不重叠
- 等级内保留一定区分度
- 与 Z 分数分布保持一致的分段结构

### 8.2 等级对应的 Z 带宽（zMin ~ zMax）
- G1：[1.75, 3.1]
- G2：[1.25, 1.75]
- G3：[0.75, 1.25]
- G4：[0.25, 0.75]
- G5：[-0.25, 0.25]
- G6：[-0.75, -0.25]
- G7：[-1.25, -0.75]
- G8：[-1.75, -1.25]
- G9：[-3.1, -1.75]

### 8.3 等级内线性插值
对每个等级内的学生集合，计算该等级内原始分最大最小值：
- sMax = max(score)
- sMin = min(score)

对每条记录：
- 若 sMax == sMin（该等级全员同分）：
  - zAssigned = zMax（该带宽上界）
- 否则：
  - zAssigned = zMin + ((score - sMin) / (sMax - sMin)) * (zMax - zMin)

### 8.4 边界截断（Cap）
最终 zAssigned 被强制截断到 [-3.1, 3.1]：
- zAssigned > 3.1 → 3.1
- zAssigned < -3.1 → -3.1

## 9. Z赋分差值（zAssignedDiff）

当 entryZAssigned 与 currentZAssigned 都存在时：
- zAssignedDiff = currentZAssigned - entryZAssigned
否则为空。

该值用于反映学生在“赋分尺度”上的净变化。

## 10. 进退步判定（progressStatus / progressValue）

### 10.1 前置条件
若 entryZScore 或 currentZScore 任一为空：
- progressStatus = null
- progressValue = null

### 10.2 Z 分差
zDiff = currentZScore - entryZScore

### 10.3 判定规则
- |zDiff| < 0.25：
  - progressStatus = 保持
  - progressValue = 0
- zDiff ≥ 0.25：
  - progressStatus = 进步
  - levels = 1 + floor((zDiff - 0.25) / 0.5)
  - progressValue = levels（正数）
- zDiff ≤ -0.25：
  - progressStatus = 退步
  - abs = |zDiff|
  - levels = 1 + floor((abs - 0.25) / 0.5)
  - progressValue = -levels（负数）

### 10.4 直观解释
- 0.25 个标准差以内视为“保持”
- 超过 0.25 后，每额外 0.5 个标准差上升（或下降）增加一个“等级”

## 11. 数据评价（班级/老师）计算逻辑

评价不是重新跑“排名/等级”算法，而是基于“数据计算结果”进行聚合与评分。

### 11.1 聚合维度
按 subject 先分组，再按 groupType 分组：
- 班级评价：groupType=CLASS，groupName=className
- 老师评价：groupType=TEACHER，groupName=teacher

### 11.2 评价指标与公式

#### 11.2.1 学业综合实力（academicStrength）
用“本次等级分布”计算加权平均：
- 等级权重（GRADE_WEIGHT）：
  - G1=90, G2=80, G3=70, G4=60, G5=50, G6=40, G7=30, G8=20, G9=10
- 对每个等级 g：
  - 占比 p(g) = count(g) / n
  - 累加 p(g) * weight(g)
得到 academicStrength。

解释：本次等级越靠前，占比越高，综合实力越高。

#### 11.2.2 保持值（keepValue）
仅统计 progressStatus == 保持 的学生，并按其“入口等级”做权重：
- keepWeight(g) = weight(g) - 10
- keepValue = Σ( countKeep(g)/n * keepWeight(g) )

解释：越高入口等级保持住，其贡献越大。

#### 11.2.3 进步值（progressValue）
对 progressStatus == 进步 的学生逐个累加：
- 只计入 progressValue > 0 且 entryGrade 不为空
- 对于每个学生：
  - 从其入口等级往上跨 levelsUp 个等级
  - 逐级累加目标等级的 weight
  - 再乘以 1/n

解释：高段位继续进步的价值更高；进步跨越越多等级，累计权重越多。

#### 11.2.4 退步值（declineValue）
对 progressStatus == 退步 的学生逐个累加：
- 只计入 progressValue < 0 且 entryGrade 不为空
- levelsDown = abs(progressValue)
- 从入口等级往下跨 levelsDown 个等级
- 逐级累加 (100 - weight(grade))
- 再乘以 1/n

解释：退步越多等级、且从高段位退步，惩罚更大（因为 100 - weight 越大）。

#### 11.2.5 相对进步率（relativeProgressRate）
relativeProgressRate = (keepValue + progressValue * 2.0) / ((declineValue + 1.0) * 1.5)

解释：
- 进步给予双倍权重（*2.0）
- 退步在分母抑制，并加 1.0 防止为 0
- 额外乘 1.5 做整体缩放

### 11.3 排序规则（评价结果列表）
按：
1) subject 升序
2) relativeProgressRate 降序

## 12. 默认科目与展示规则（与算法关系）

- 数据评价页默认科目为“总分”，因此常见使用路径下：
  - 班级评价与老师评价默认展示“总分”下的聚合结果
- 导出 Excel 的科目 sheet 顺序固定，保证汇报口径一致。

## 13. 边界与异常处理建议（当前逻辑）
- stdDev=0 时 Z 分数为 0（整组同分或仅一人），进退步依赖 Z 分差可能会出现全部保持或空值。
- 同分并列时 percentile 由 rank/n 决定，同分学生等级相同，但等级边界处可能出现“跳级”现象，属于可接受统计离散。
- 评价指标对 entryGrade/currentGrade 依赖较强，若某些记录缺失等级字段，会被忽略或降低有效样本贡献。
